# atlassian-notes

A small local web app for refining Jira tickets privately. It pulls tickets from Jira (read-only) into tabbed table views and lets you keep your own markdown notes beside each one, plus notes written by a Claude Code grooming skill. Notes are plain files on your disk. Nobody else sees them.

## Install

Requires Node 22.18 or newer.

```sh
npm install
npm run setup   # asks for site, email, token, default project; checks the connection
npm start       # builds the CSS/JS, starts on http://localhost:4317 and opens your browser
```

Your Jira settings are saved to `~/.config/atlassian-notes/.env` (mode 600), outside this folder. Set `ATLASSIAN_NOTES_ENV` to use a different file. The app never reads a `.env` in the app folder. `.env.example` lists every key (`NOTES_DIR`, `REFRESH_MINUTES`, `PORT`, `OPEN_BROWSER` are optional).

## The API token

Create one at <https://id.atlassian.com/manage-profile/security/api-tokens>.

- Recommended: a scoped token ("Create API token with scopes") with only `read:jira-work` and `read:jira-user`. Scoped tokens can't go through your `*.atlassian.net` address, so requests go via `api.atlassian.com`. `npm run setup` handles this: answer "y" to "scoped token" and it looks up your site's cloud id and stores it as `JIRA_CLOUD_ID`. Scoped tokens expire (at most one year), so re-run `npm run setup` when it stops working.
- A classic token also works. The app only ever makes GET requests either way.

Behind a corporate proxy that inspects TLS, Jira errors may say "unable to get local issuer certificate": point Node at your company's root certificate with `NODE_EXTRA_CA_CERTS=/path/to/corp-root.pem npm start`.

## Where your data lives

Everything personal lives in `NOTES_DIR` (default `~/atlassian-notes-data`), never in the app folder:

```
views.yaml            tabs: name, JQL, columns, filters
board.yaml            your personal board: columns and card placement
columns.yaml          custom columns + Jira field mapping
jira/notes/KEY.md     your notes
jira/groom/KEY.md     groom output written by Claude (the app only reads it)
jira/tickets/KEY.md   generated ticket files for Obsidian (generated; edits are overwritten)
scratchpad.excalidraw the Scratchpad tab's drawing
links.yaml            optional links in the top bar
reading.yaml          reading list statuses, categories, prompts and the Claude prompt
analysis.yaml         optional: charts for each view's Analysis side
reading/items/<id>.md a reading list item: details at the top, your note below
reading/groom/<id>.md Claude's summary of a reading item (the app only reads it)
.cache/               last Jira results, so the app opens instantly
```

On first run, `views.yaml` and `columns.yaml` are created from `examples/` with your default project key filled in. Hand edits are picked up live. Note: the app rewrites `views.yaml` when you change a view in the UI, so comments you added to it are lost.

## Use with Obsidian

Open your notes folder (`NOTES_DIR`, default `~/atlassian-notes-data`) as an Obsidian vault.

- `jira/tickets/` is generated by the app after each refresh, one file per fetched ticket. Edits there are overwritten, so write in your notes instead.
- Links use full paths because notes, groom and ticket files share a name. When linking a ticket from your own notes, write `[[jira/tickets/AAA-1|AAA-1]]`.
- Suggested graph colour groups: `path:jira/tickets`, `path:jira/notes`, `path:jira/groom`, `path:reading`.
- `.cache` is hidden from Obsidian automatically.

## views.yaml and columns.yaml

`views.yaml`: each view has an `id`, `name`, `jql`, ordered `columns` (each `id`, optionally `display: truncate`) and optionally `limit` (default 500) and `search`, the keyword from the search box beside the JQL bar. Refreshes add `AND text ~ "<search>"` to the query, before any `ORDER BY`; the bar shows the added part in colour, and × or Esc in the box clears it. Your `jql` itself is never changed. See `examples/views.example.yaml`. Built-in column ids: `key`, `summary`, `status`, `type`, `priority`, `assignee`, `reporter`, `storyPoints`, `parent`, `labels`, `components`, `sprint`, `updated`, plus `note` and `groom`, and the sortable timestamps `noteUpdated` ("Note updated") and `groomed` ("Groomed"). These built-in ids (including `noteUpdated` and `groomed`) are reserved: a custom column in `columns.yaml` can't use any of them, and `columns.yaml` is reported as broken if one does.

`columns.yaml`: see `examples/columns.example.yaml`.

```yaml
jiraFields:
  storyPoints: customfield_10016   # differs per Jira site
  sprint: customfield_10020
custom:
  category:
    label: Category
    type: select                   # or: text
    options:
      Tech debt: "#e5b45b"
```

Optional keys:

- `jiraFields.acceptanceCriteria`: the `customfield_NNNNN` holding acceptance criteria, if your site has one. It is shown in the ticket drawer and included when you copy the ticket.
- `groomPrompt`: the text that Copy → "Groom prompt for Claude" copies. Placeholders `{key}`, `{url}` and `{groomPath}` are filled in per ticket. The default asks for a skill called `groom-work-item` (the author's own); change it to name your own grooming skill or prompt.

Finding your field ids: open `https://<your-site>/rest/api/3/field` in a browser while logged in to Jira and search for "Story point estimate" and "Sprint". The `id` is the `customfield_NNNNN` value. Custom column values are stored in each note's front matter. Option lists are only edited in this file, but you filter on them from the UI.

## Analysis

Every view tab has a **Tickets | Analysis** toggle at the left of its header (also "Show analysis" in ⌘K). Analysis draws charts from the tickets the view already fetched (before your filter chips), so it never calls Jira itself. The browser remembers which side each view was on.

Charts come from an optional `analysis.yaml` in your notes folder; copy `examples/analysis.example.yaml` to start. A view that isn't listed gets a default set: the sprint countdown (when its tickets share an active sprint), headline numbers, progress, open work per person, needs attention, and a bar chart by component. Edits show up straight away. If the file has a mistake, the red bar says what and where, and every view shows the default charts until it's fixed.

- **settings:** `measure` (`points` or `tickets`), `movingDays`, `stalledDays`, `lowLoad`, `freeze` (the release freeze as a working day of the sprint, e.g. `W2/D3`), `blocked` (`statuses`, `flagField`, `links`) and `fields` (extra Jira field ids to fetch). A view can override any of these under `views.<id>.settings`, except `fields` and `blocked.flagField`, which apply to all views.
- **groups:** named groups of components, e.g. a `product` set where Payments is `[payments-api, payments UI, infra]`, or a `layer` set where Frontend is `["* UI"]`. `*` matches anything and case doesn't matter. A ticket counts in every group one of its components matches; anything matching none is **Other**.
- **views:** for each view id, `charts:` in order. Each is a type, or `{type, by, title, measure}`:

| type | shows |
|---|---|
| `countdown` | where today falls in the sprint (W1/D3), the working days, days to the freeze and days left |
| `headlines` | Done %, Moving, Stalled, Blocked (and unassigned) |
| `progress` | done / in progress / to do as one bar |
| `bars`, `donut` | a split `by` something |
| `statusBars` | a split `by` something, each row by status, with its share |
| `complete` | % complete by points and by tickets |
| `completeBy` | % complete for each value of `by` |
| `perPerson` | open work per assignee, with anyone under `lowLoad` marked low |
| `attention` | blocked tickets (and why), then stalled ones |

`by` is `assignee`, `status`, `type`, `priority`, `component`, `label`, `group:<set>`, `column:<your column id>` or `field:<jira field id>` (listed in `fields`).

- **Stalled:** in progress, not blocked, and not updated for more than `stalledDays`. **Moving:** in progress, not blocked, updated within `movingDays`. **Blocked:** not done, and in a `blocked.statuses` status, flagged in Jira (when `flagField` is set), or with an "is blocked by" link to a ticket that isn't done.
- Working days are Monday to Friday. Sprint dates, the flag and extra fields arrive with the next refresh after you add them.
- With points, unestimated tickets count as 0 and the chart says how many there are. Someone whose open work includes unestimated tickets is never marked low.
- When a ticket is in more than one group, each share is of the view's real total, so shares can add up to more than 100% (the chart says so).
- **Click-through:** click a bar, a donut slice or its legend, a person, or a headline number to see just those tickets on the Tickets side. A "From analysis" chip shows what you clicked; it isn't saved, and × (or going back to Analysis, or another tab) clears it. Click a row under Needs attention to open the ticket.

## Kanban

The **Kanban** tab (far left) is a personal board for tickets you want to come back to, whatever view or search they came from. Moving a card never touches Jira.

- **Starring:** click the ☆ in the first column of any table view to put a ticket at the bottom of the first column. Click the ★ again to take it off. The ✕ on a card (shown on hover or focus) does the same.
- **Moving cards:** drag a card to another column or to a new place in its column; a blue bar shows where it will land. With a card focused (Tab to it), Alt+←/→ moves it to the previous or next column and Alt+↑/↓ moves it up or down one place. Enter opens the ticket.
- **Notes:** click a card's note box (or "+ add note") to edit the same note that the table and ticket panel use.
- **Columns:** they come from `board.yaml` in your notes folder, created from `examples/board.example.yaml` on first run. Edit the file to add, rename or reorder columns; the board updates live.

  ```yaml
  columns: [Backlog, Doing, PEN, Done]
  archiveColumn: Done
  noteColumn: Doing       # optional; where a note on a searched-for ticket puts it (default Doing, else the first column)
  cards:                  # written by the app; order in a list = order on the board
    Backlog: []
    Doing: [PAY-412]
  ```

  A card under an unknown column goes to the first column, and a repeated key is kept once. If `board.yaml` can't be parsed, the board shows the error and its controls (and the table stars) are disabled until you fix the file; the app never rewrites a file it couldn't read.
- **Ticket search:** type a key (any case, e.g. `pay-412`), just the number (`412`, in your default project) or paste a Jira link (`…/browse/PAY-412`, or a board link with `?selectedIssue=PAY-412`) into the box at the right of the tabs (⌘S) and press Enter to open that ticket's panel, whether or not it is in a view. Esc clears the box. The panel has its own ★ that adds the ticket to the first column or removes it. If the ticket isn't already on your board, saving a non-empty note in a panel opened this way moves it to the `noteColumn` (default Doing). Tickets already on the board are never moved by a note, and notes written from the table views don't touch the board.
- **Archive:** the `archiveColumn` lane has an **Archive all** button (click it, then click "Archive N cards?" within 4 seconds). It only takes those cards off the board, like un-starring them. Your notes are kept.
- **Refresh:** the board fetches its tickets from Jira by key, independently of your JQL views. A ticket Jira can't find (deleted, or no permission) shows as "not found in Jira" and the rest of the board still loads.

### Using your board with Claude

`board.yaml` plus `jira/notes/<KEY>.md` describe the whole board, so Claude can read it as plain files. For example:

> Read my board.yaml and the notes for everything in Doing, then tell me which of them is ready to pick up and what is blocking the rest.

## Reading list

The **Reading list** tab (the glasses, third from the left) keeps links you mean to read next to the Jira work they belong to: Confluence pages mostly, but also videos, articles and Slack threads.

- **Add:** paste a link into the bar at the top and press Enter. It's added as the first status (Pending) with a title guessed from the link (a Confluence link carries the page name). Pasting a link that's already there opens it instead. The app never fetches the page, a preview or an icon.
- **Sub-tabs:** one per status (Pending, Open questions, Complete) plus All, with counts. Filter by category or linked ticket; click a heading to sort.
- **★** puts the item on your Kanban, like a ticket. Archiving the Kanban's last column marks reading items there Complete (`doneStatus`); nothing else moves automatically.
- **Side panel:** click a title. Set status, category and linked tickets, edit the title or link, and write your note (a literature note in your own words, a question, a todo). The reading prompts sit above the note. A ticket's own panel lists the reading linked to it.
- **Copy** offers the link, your note, the item + note for Claude, and a prompt for Claude that tells it where to save its summary (`reading/groom/<id>.md`, same idea as the groom file contract below). The summary shows in the panel and the Groomed column.
- **Delete** (in More) moves the item and any Claude summary to `.cache/trash/reading/` in your notes folder and removes its Kanban card. Nothing is deleted outright.

`reading.yaml` is created on first run from `examples/reading.example.yaml`:

```yaml
statuses: [Pending, Open questions, Complete]   # first = default for new items; each is a sub-tab
doneStatus: Complete                            # used by Kanban archive
categories: [Architecture, RFC, Discussion, Learning]
prompts:                                        # shown above the note editor
  - Why am I reading this?
  - What is it saying, in my own words?
  - How does it connect to the work, and to what I already know?
  - What do I question or disagree with?
  - What will I do next?
groomPrompt: "Read {url} ({title}). Write a reading summary to {groomPath} …"
```

The prompt can use `{url}`, `{title}`, `{tickets}`, `{groomPath}` and `{notePath}`. While the file is broken, item fields can't be changed (notes still can) and the error bar says why.

In Obsidian, items link to their tickets through the `links` field (kept in step with `tickets`), and ticket files list the reading that links them. If a linked ticket isn't in any view or on the Kanban, it shows as its key only.

## Command palette

Press **⌘K** (Ctrl+K on Windows/Linux) anywhere, even on the Scratchpad canvas, to open the command palette. Commands are grouped under headings: **Ticket** (type a key such as `pay-412`, a number or a Jira link to open it), **Go to** (Kanban, Scratchpad, Reading list, your views and top-bar links), **View** (refresh, edit the JQL or view, open the JQL in Jira, add or delete a view), **Kanban** (refresh, on the board), **Reading** (add a link, show a status; paste a URL to get "Add … to reading list") and **Theme**. Type to filter. Words match in any order, and typing a heading such as `theme` lists that group. ↑/↓ choose, Enter runs, Esc or ⌘K closes. ● marks the current tab and theme.

## Groom file contract

Claude (or any tool) writes `$NOTES_DIR/jira/groom/<KEY>.md`:

```markdown
---
key: PAY-412                 # optional; the app fills it in
jira_id: "10234"             # optional; the app fills it in
readiness: Needs work        # short free text
summary: 3 gaps in AC; suggest split into retry + alerting
groomed_at: 2026-10-22T14:03:00Z
---
(full groom output, any markdown)
```

The table shows `readiness`, `summary` and age. Without front matter, the first non-empty line is shown. The app never changes the body of a groom file.

To wire up your own Claude skill (for example `groom-work-item`), add this line to it:

> Save your output to `$NOTES_DIR/jira/groom/<KEY>.md` (default `~/atlassian-notes-data`) with front matter `readiness`, `summary` and `groomed_at` (ISO timestamp), followed by the full write-up.

## Top-bar links

Add your own links (a roadmap tool, a wiki, dashboards) to the right of the ticket search with a `links.yaml` in your notes folder. Copy `examples/links.example.yaml` to start: each link has a `name`, a `url` (https or http only), an optional `icon` (a built-in name such as `map`, `book` or `chart`, or an emoji; without one the button shows the name) and an optional `newTab` (default `true`). Changes show up straight away; a bad entry is skipped with a warning and the rest still show. The app never contacts these sites itself: it only opens them when you click.

## Scratchpad

The brush tab next to Kanban is a single [Excalidraw](https://excalidraw.com) canvas for sketching while you refine. It saves itself to `scratchpad.excalidraw` in your notes folder a moment after each change (Excalidraw's own file format, so Obsidian's Excalidraw plugin can open it too). Excalidraw and its fonts are bundled into the app at build time (`npm start` builds them into `public/vendor/`), so nothing is fetched from the internet; sharing links, AI features and the online library browser are off or unreachable. Chinese, Japanese and Korean text uses a fallback font. Close Obsidian while drawing if it has the notes folder open, and reopen it when you're done.

## Themes

The app uses the Carbon theme by default (near-black, one yellow accent, square edges, JetBrains Mono, bundled locally). Pick another of the ten themes, such as Tokyo Night, Catppuccin, Gruvbox or Nord, from the swatch button in the tab bar. Your choice is stored in this browser only. The themes are copied from the author's forge project.

## Sharing

`npm run pack` writes `atlassian-notes.zip` next to the app folder. It contains one top-level `atlassian-notes/` folder with only code, examples and this README: no token, env files, notes, cache or `node_modules`. Send that. Recipients unzip it, `cd atlassian-notes`, then follow Install above.

## Privacy

- Only HTTP GET requests, only to your Jira site (or `api.atlassian.com` for scoped tokens). The app cannot change anything in Jira.
- The server listens on 127.0.0.1 only. The page loads nothing from outside (CSP `default-src 'self'`; images may also be in-memory `data:`/`blob:` URLs, for pictures dropped into the Scratchpad): no CDNs, fonts, analytics or telemetry.
- The token lives only in `~/.config/atlassian-notes/.env`; `setup` never prints it.
